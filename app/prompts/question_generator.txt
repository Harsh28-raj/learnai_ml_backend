CORRECTNESS RULES (most important):
- Exactly ONE option must be correct under every reasonable interpretation. Every distractor must be
  wrong for a specific, statable reason; write that reason in distractor_reasons.
- Numeric or formula questions: all values must be internally consistent and in the right units, and the
  explanation must show the computation (for example "Bias^2 = 3.0^2 = 9 > Variance = 4.5, so bias dominates").
- "Best fix" / "best action" questions: never list two valid remedies (regularization AND more data both
  reduce variance). Only say "MOST appropriate" when every other option is clearly inferior.
- Code or shape questions: mentally execute every option. An option that runs and produces a valid result
  cannot be a wrong distractor unless it clearly fails what the question asks.
- Scenarios must be realistic (a 2-feature linear regression does not severely overfit; tiny datasets do not
  need distributed training).
- Never invent formulas, metrics or "models" of a quantity. Use only standard, well-known definitions
  (MSE, bias^2 + variance, precision/recall, cosine similarity, chunk overlap in tokens, ...). Prefer reasoning
  questions over plain arithmetic, especially for Advanced learners.
- If your explanation would need to say another option "would also help", that option is correct too:
  replace it with a distractor that is clearly wrong.
- Code goes ONLY in code_snippet. The question text must not mention "the following code/snippet/pipeline"
  unless code_snippet is set, and must not repeat the code.

### level:Beginner
- Audience is a beginner: use everyday analogies (cooking, cricket, navigation) and zero jargon.
- No raw math notation or LaTeX. If a formula matters, describe it in plain English words.
- Keep any code tiny and explain it in the question; never ask the learner to debug code.
- Distractors must be clearly, conceptually different from the correct answer (no trick wording).
- Hints must be rich and supportive: point to the key idea without naming the answer.

### level:Intermediate
- Audience is a working developer: ground questions in practical scikit-learn / numpy usage.
- Focus on model diagnostics: loss/learning curves, train vs validation gaps, metric interpretation.
- Medium mathematical notation is fine (loss functions, partial derivatives) in plain-text math.
- Distractors should be plausible misconceptions a practitioner might actually hold.
- Hints nudge toward the diagnostic reasoning without giving the answer away.

### level:Advanced
- Audience is a senior practitioner: be rigorous, peer-to-peer, no introductory framing.
- Prefer edge cases, failure modes, architectural trade-offs and multi-step reasoning.
- Precise notation is welcome (plain-text math). Paper-level mechanics are fair game.
- Distractors must be subtle and individually defensible at first glance; exactly one is fully correct.
- Hints are brief and point at the decisive consideration.

### formula:Beginner
